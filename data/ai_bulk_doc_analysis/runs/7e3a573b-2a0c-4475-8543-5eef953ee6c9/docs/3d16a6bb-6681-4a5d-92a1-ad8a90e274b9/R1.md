Here is the summary of the key points from the Frontend UI/UX Specification document:

Design Principles:
1. Clarity over power - users should never guess what to do next
2. Progress visibility - async AI systems must always show status
3. One primary action per panel - secondary actions stay subtle
4. Deterministic feel - system should feel predictable, not "chatty"
5. Fail visibly, recover cleanly - errors should be actionable

Global Layout:
- Three-panel layout (left to right): Documents, Prompt Chain, Run & Output
- Top bar with app name, session info, user menu
- Toast system for success, in-progress, and error notifications

Panel 1 - Documents:
- PDF upload with conversion status tracking
- Document list with filename, status, and delete action for errors

Panel 2 - Prompt Chain:
- Saved chain selector with chain details (name, description, step count)
- No inline prompt editing

Panel 3 - Run & Output:
- Run button enabled when docs converted and chain selected
- Live progress table with filename, step, status, token usage
- Download actions per document and for all outputs

States & Feedback:
- Use skeleton loaders over spinners for loading states
- Provide clear empty and error states

Accessibility & Polish:
- Keyboard navigable, clear focus states, consistent spacing/typography

Success Criteria:
1. Upload PDFs without guidance
2. Understand conversion progress
3. Select a chain confidently 
4. Run and download outputs without confusion
