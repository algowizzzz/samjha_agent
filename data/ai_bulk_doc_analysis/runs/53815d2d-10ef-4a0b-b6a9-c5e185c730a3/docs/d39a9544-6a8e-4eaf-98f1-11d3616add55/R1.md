Here is a summary of the key points from the Frontend UI/UX Specification document:

Design Principles:
- Clarity over power - users should never guess what to do next
- Progress visibility - async AI systems must show status
- One primary action per panel, with secondary actions staying subtle
- Deterministic feel - system should feel predictable, not "chatty"
- Fail visibly, recover cleanly - errors should be actionable

Global Layout:
- Three-panel layout (Documents, Prompt Chain, Run & Output)
- Top bar with app name, session info, and user menu
- Toast system for success, in-progress, and error notifications

Panel 1 - Documents:
- PDF file upload with conversion status tracking
- Error handling and reversible document deletion

Panel 2 - Prompt Chain:
- Selection of pre-defined prompt chains
- Read-only chain detail view, no inline editing

Panel 3 - Run & Output:
- Run button enabled when all docs converted and chain selected
- Live progress table with token usage
- Download actions for individual documents or all outputs

Key UX Notes:
- Avoid chat-style UI, inline prompt editors, hidden auto-runs, and multi-step wizards
- Success criteria: first-time user should be able to upload, understand progress, select chain, and run/download without confusion

The overall goal is to design a professional, simple, and intuitive UI that integrates all approved features with minimal cognitive load and clear system feedback.
