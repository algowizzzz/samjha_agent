Here is a summary of the key points from the Frontend UI/UX Specification document:

Design Principles:
- Clarity over power - users should never guess what to do next
- Progress visibility - async AI systems must show status
- One primary action per panel, with secondary actions staying subtle
- Deterministic feel - system should feel predictable, not "chatty"
- Fail visibly, recover cleanly - errors should be actionable

Global Layout:
- Three-panel layout (Documents, Prompt Chain, Run & Output)
- Top bar with app name, session info, and user menu
- Toast system for success, in-progress, and error notifications

Panel 1 - Documents:
- PDF upload with conversion status tracking
- Document list with filename, status, and delete action

Panel 2 - Prompt Chain:
- Saved chain selector with chain details
- No inline prompt editing

Panel 3 - Run & Output:
- Run button enabled when docs converted and chain selected
- Live progress table with filename, step, status, and token usage
- Download actions per document and for all outputs

States and Feedback:
- Skeleton loaders, empty states, and clear error handling
- Accessibility and polish requirements

Success Criteria:
- First-time user should be able to upload, understand progress, select a chain, and run/download without confusion.
