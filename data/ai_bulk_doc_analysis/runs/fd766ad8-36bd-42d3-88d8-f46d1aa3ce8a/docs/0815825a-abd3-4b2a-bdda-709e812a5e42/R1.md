# Frontend UI/UX Specification Summary

## Document Overview
**Target Audience:** Frontend Engineers & UI/UX Designers  
**Primary Goal:** Design a professional, simple, and intuitive UI that integrates all approved features across three panels with minimal cognitive load and clear system feedback.

## Core Design Principles
1. **Clarity over power** – Users should never guess what to do next
2. **Progress visibility** – Async AI systems must always show status
3. **One primary action per panel** – Secondary actions stay subtle
4. **Deterministic feel** – System should feel predictable, not "chatty"
5. **Fail visibly, recover cleanly** – Errors should be actionable

## System Architecture

### Global Layout Structure
- **Three-panel layout** (left → right):
  - Panel 1: Documents
  - Panel 2: Prompt Chain
  - Panel 3: Run & Output

### Global UI Elements
- **Top bar:** App name, session name/ID (read-only), lightweight user/profile menu
- **Toast system:** Success (green), in-progress (neutral), error (red, dismissible)

## Panel Specifications

### Panel 1 — Documents (Ingestion & Conversion)
**Primary Goal:** Upload documents and ensure successful conversion

**Key Components:**
- Input type selector (PDF enabled, others "Coming Soon")
- Upload button (primary CTA) with file count display
- Document list with filename, status badge, and action icons
- Clickable rows leading to document detail drawer

**UX Requirements:**
- Auto-start conversion after upload
- Clear error messaging with deletion options
- Safe, reversible document deletion with confirmation

### Panel 2 — Prompt Chain (Configuration)
**Primary Goal:** Select or configure logic to run on documents

**Key Components:**
- Saved chain selector with chain cards showing name, description, and step count
- Chain detail view (read-only) displaying ordered steps and descriptions

**UX Requirements:**
- No inline prompt editing
- Clear labeling of invalid/incomplete chains
- Lightweight chain selection without modal overload

### Panel 3 — Run & Output (Execution)
**Primary Goal:** Run chain and retrieve outputs confidently

**Key Components:**
- Run button (disabled until prerequisites met)
- Run progress table with per-document rows showing filename, current step, status, and token usage
- Completion summary with processing statistics
- Download actions for individual and bulk outputs

**UX Requirements:**
- Live progress updates
- Token usage visibility for cost awareness
- Failed documents don't block successful ones

## System States & Feedback

### Loading States
- Skeleton loaders preferred over spinners

### Empty States
- Panel 1: "Upload documents to begin"
- Panel 2: "Select a saved chain"
- Panel 3: "Ready to run"

### Error States
- Inline errors for document-level issues
- Toast notifications for system-level issues

## Technical Requirements

### Accessibility & Polish
- Keyboard navigation support
- Clear focus states
- Consistent spacing and typography
- No dense text blocks

### Frontend-Backend Contract
- Frontend treats backend as source of truth
- All async work is status-driven
- Frontend never infers state

## Exclusions (What NOT to Build)
- No chat-style UI
- No inline prompt editors
- No hidden auto-runs
- No multi-step wizards

## Success Criteria
A first-time user should be able to:
1. Upload PDFs without guidance
2. Understand conversion progress
3. Select a chain confidently
4. Run and download outputs without confusion

**Critical Rule:** If any of these fail → UI is too complex.
